# 异常处理

| 异常错误 | 含义 | 处理类型 | 处理方式 |
|---|---|---|---|
| 登录失效 / `status: error` / `AUTH_REQUIRED` / `AUTH_FAILED` | Token 不存在或已失效 | 重试 | 执行 `login` 命令重新授权 |
| `10000` | 登录态失效 | 重新登录 | 先执行 `login --force` 强制刷新并重试，仍失败则提示用户重新登录。详见下方 Token 失效自动检测 |
| `10001` | 必填参数校验未通过 | 校验补全 | 检查手机号是否为脱敏号码(含\*\*\*\*)或缺失，按优先级自动填写真实号码：用户明确提供的真实电话 > get_address_info返回的真实号码 > 登录账号的手机号，严禁使用脱敏号码下单，补全后重新提交 |
| `10002` | goodTypes与goodTypeNames不匹配 | 校验补全 | 检查goodTypes/goodTypeNames映射是否一致并修改 |
| `10003` | 服务器偶发异常/超时 | 透传 | 提示用户：「服务器暂时开小差啦，请稍后重试。」 |
| `10309` | 配送费已动态变化 | 二次确认 | 重新询价和预览订单，展示并提示用户「配送费发生动态变化，请重新确认下单」 |
| `10310` | 账号被风控限制 | 透传 | 提示用户：「系统检测到您的账号存在异常行为，已被限制下单。如有疑问请前往美团app或小程序咨询客服」不重试 |
| `10311` | orderToken失效 | 重试 | 重新询价并再次下单 |
| `10392` | 帮买场景误传了 service-type（如 4033） | 校验修正 | 帮买场景不传 `--service-type`，去掉该参数后重新询价并下单 |
| `10112` | 取件/购买地址所在区域未开通服务 | 透传 | 提示用户：「该地址所在区域暂未开通跑腿服务，请重新选择地址。」 |
| `10113` | 地址所在城市未开通服务 | 透传 | 提示用户：「该地址所在城市暂未开通跑腿服务，请更换为已开通服务的城市。」 |
| `10114` | 交通管制等特殊原因无法配送 | 透传 | 提示用户：「因临时交通管制，该地址暂时无法配送，请稍后重试。」 |
| `10115` | 配送距离超出最大范围 | 透传 | 提示用户：「收发件地址距离过远，超出配送范围，请选择更近的地址。」 |
| `10116` | 无效地址 | 透传 | 提示用户：请提供更精确的地址 |
| `11000` | 提单内容包含不规范内容 | 透传 | 提示用户：「订单内容包含不规范内容，请修改后重新下单。」 |
| `11003` | 商品信息不符合平台规范 | 透传 | 提示商品信息不符合平台规范，包含违禁物品或敏感词，请修改后重新下单。 |
| `11004` | 备注内容不符合规范 | 透传 | 提示用户：「备注内容不符合规范，请修改后重新下单。」 |
| `11005` | 发件人姓名包含不规范内容 | 透传 | 提示用户：「发件人姓名包含不规范内容，请修改后重试。」 |
| `11006` | 发件地址包含不规范内容 | 透传 | 提示用户：「发件地址包含不规范内容，请修改后重试。」 |
| `11007` | 收件人姓名包含不规范内容 | 透传 | 提示用户：「收件人姓名包含不规范内容，请修改后重试。」 |
| `11008` | 收件地址包含不规范内容 | 透传 | 提示用户：「收件地址包含不规范内容，请修改后重试。」 |
| `11016` | 物品描述不符合规范 | 透传 | 提示用户：「配送物品描述不符合规范，请修改后重新下单。」 |
| `40001` | 不支持代购药品/医疗器械 | 透传 | 提示用户：「跑腿不支持代购药品和医疗器械，请选择其他品类。」 |
| `10401` | 配送费计算失败 | 重试 | 重新询价并再次下单 |
| POI 搜索无结果 | POI搜索无结果 | 透传 | 提示用户提供更精确的地址（含街道/楼号） |
| 费用预览失败 | 费用预览失败 | 重试 | 检查地址坐标是否正确或尝试缩短距离 |
| 网络超时 | 网络超时 | 重试 | 提示用户：网络问题超时，请检查网络/VPN后重试 |
| 响应解析失败 | 接口响应异常 | 重试 | 提示用户：接口异常，请检查网络/VPN连接后重试 |

## Token 失效自动检测

当任何接口返回 `code: 10000` 且 `message` 为"未知错误"时，应视为 Token 服务端过期：

1. 自动执行 `login --force` 强制重新授权
2. 授权成功后重试原请求
3. 若重试仍失败，按实际错误码处理

> ⚠️ `login`（不带 `--force`）仅检查本地缓存文件，不验证服务端有效性。因此本地 Token 存在 ≠ 服务端有效，收到 10000 时必须使用 `login --force` 强制刷新。
